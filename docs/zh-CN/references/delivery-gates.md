# 交付阶段、测试与设计门槛

各阶段描述职责和验收条件，可以合并执行。轻量变更可以标记某阶段不适用，并说明原因。接收方代表一项职责，不要求新设角色、Agent 或用户审批。只执行适用于当前任务的阶段及项目要求的检查。

## 从需求到发布

| 阶段 | 预期交付物 | 通过与验收条件 | 失败后返回的位置 |
| --- | --- | --- | --- |
| 启动/范围 | 用户问题、目标、成功标准、范围/非目标、依赖、风险和任务 | 需求负责人能够判断工作为何需要、包含什么及其获授权的范围；未知事项有明确去向 | 在保留可独立推进工作的同时澄清目标/范围 |
| PRD/规格 | 角色、主要流程、业务规则、权限、例外、验收条件和需求版本 | 设计/开发/测试对可观察行为没有重大歧义；小型变更可直接写在任务卡上 | 需求或变更记录 |
| 原型/UI/UX | 状态与交互、内容和组件、视觉基线、适用的视口/主题/语言 | 业务流程可用，复用既有约定，实际检查适用状态，且设计/开发认可 | 设计任务和缺陷 |
| 技术拆分/约定 | 模块职责、数据权威来源、接口/错误、依赖、切片和测试计划 | 上下游可依约定实现/验证；兼容性和高风险取舍已解决 | 规格/约定任务 |
| 开发 | 受控范围内的代码/配置/文档、必要测试、差异和自检 | 实现符合规格，必需检查通过，遗留项明确，交给测试的候选版本可识别 | 实现任务 |
| 测试 | 场景清单、实际执行结果、覆盖边界、缺陷和复测 | 适用的必需项都有有效证据；失败、跳过和未知不能记为通过 | 缺陷修复或测试准备 |
| 产品/设计验收 | 候选版本与需求及视觉基线的对照、证据和遗留处置 | 指定接收方确认范围与结果；分别记录内部验收和用户验收 | 相关需求/设计/实现任务 |
| 发布准备 | 精确候选版本、适用 CI/构建证据、发布步骤、依赖、观察和回滚评估 | 证据对应当前候选版本；阻塞已解决；满足授权和项目发布要求 | 缺口任务；不能拿旧版本的通过结果代替 |
| 发布 | 使用项目既有方式交付的版本/产物及实际执行记录 | 目标环境、候选身份、配置/迁移和健康状态符合项目要求 | 按既定方案停止或回滚，并保留事件记录 |
| 发布后观察 | 关键流程/错误/反馈观察、交付记录、问题和经验 | 约定的观察范围有证据；异常已记录，后续责任明确 | 缺陷与改进闭环 |

发布方式、必需检查、备份/恢复和观察周期由目标项目决定。不要把某项目的容器镜像、工作流或手工步骤变成通用硬性要求。没有发布授权时，完成已授权的准备并说明缺少的最后一步；不要假定提交、推送或部署已获授权。

## 原型、UI 与 UX

先确认有效的设计版本以及现有组件/样式的来源。旧项目没有约定时，记录真实现状基线和已知不一致，再为本次变更制定局部可接受的约束；未经授权不要重设计整个网站。

针对变更范围，建立“页面/组件 × 状态 × 视口 × 主题/语言”的适用性清单；并非每个项目都要穷举完整的笛卡尔积。全站样式迁移需要完整列出受影响的入口/共享组件，并标明已迁移项、豁免原因和未验收项。只查看代表性页面不能据此宣称全站一致。

适用检查包括：

- **对齐与结构：**图标和文字基线、单行/多行垂直对齐、表头/内容列对齐、列表间距和行内按钮/输入框布局；出现错误时相邻操作不应位移。
- **间距与尺寸：**容器内边距、子项间距、首尾项外边距、滚动/固定区域、安全区和对话框/抽屉可用空间；避免重复间距、缺少外边距、溢出和遮挡。
- **内容与状态：**空/加载/失败/禁用、长文本/多语言、零值/极端值、不同数据量、权限差异和交互反馈；适用时检查键盘、焦点和辅助阅读。
- **视觉一致性：**当前设计令牌/主题、文字层级、图标尺寸和组件变体；不要用普遍居中、固定字号或固定像素规则取代项目约定。
- **UX 完整性：**主路径、返回/取消/恢复、错误纠正、关键操作确认和一致的数据含义；原型成功不代表上传、保存、外部接口或生产流程已验证。

通过实际渲染和明确对照进行验证。自动几何/视觉差异有助于发现问题；直接视觉审阅用于判断可读性和设计意图。记录实际审阅的页面/配置；不能把自动截图数量描述为逐张人工审阅。更新快照时说明预期差异；不要仅为让测试通过就接受所有新图像。

对于流程或说明图，优先呈现主路径、例外和辅助层，再按需增加细节。在实际尺寸下检查文字、连线、换行和窄屏可读性；节点数和连接数不能证明图表易读。

### 涉及 UI 工作的实际渲染验收

在既有任务或验收文档中保留简洁记录即可，无需每页另建报告。根据改动组件、条件分支和共享样式使用方确定范围，不能只列路由。默认状态下访问过页面，不能证明其条件布局已检查。

1. **状态与布局关系清单：**识别受影响元素及其关系：相邻区块/提示、父级内边距、首尾项、图文对齐和换行。选择会改变这些关系的可达状态：基础状态、每个受影响条件区域，以及业务允许时多个区域同时出现。纳入相关宽度与长内容；说明排除的组合及原因，不要求穷举全部组合，也不为测试捏造业务状态。
2. **判断前明确预期：**指出当前设计修订、组件/令牌规则或已约定的局部基线。写清预期布局关系；设计有数值时记录适当的值或范围。例如，提示与其上方摘要之间应使用项目规定的区块间距。不能统一硬套 8/16/24px，也不能把设计刻意组合的贴合区块当作错误。设计依据缺失时明确保留缺口，提出的局部基线不能冒充已批准设计。
3. **对比实际渲染：**在选定状态与宽度下实看并对照基线。间距问题应记录相邻元素边界与实际距离（纵向相邻元素为下一项 top 减去上一项 bottom），必要时核对计算样式或父级布局。内部 `gap` 不能证明元素之间的外部间距；CSS 声明和无横向溢出检查也不能代替。几何测量辅助视觉审阅，后者判断可读性、字形视觉对齐和设计意图。使用已有且允许的浏览器工具或可复现的手动证据，不为填表临时引入一套自动化技术栈。
4. **证据与验收：**每个选定用例保留候选/环境、路由/组件、可复现状态和数据准备、视口、基线引用、预期与实际、证据位置或带日期的直接观察、通过/失败/未验证及问题去向。遵守截图限制，允许的直接观察加测量可以不保存图片。浏览器、状态、基线或必需证据不可用时，记录缺失检查和下一步；不能标记 UI 已验收，也不能由构建或测试通过推断。实现状态与 UI 验收分开；依赖 UI 的发布必需门槛尚未通过时，不得宣称已具备发布条件。项目允许例外时，明确记录已获授权的取舍，不能把失败改记为通过。
5. **回归与复发：**复现用户报告的状态，并检查受影响相邻状态和共享使用方。对重复出现且可测量的问题，保留关联布局关系与基线的可运行定向断言或可重复手工检查；可行时证明修改前失败、修改后通过。判断此前漏检属于规则未读取、状态遗漏、断言缺失/错误、基线不符还是候选不同。不能把全路由访问或测试总数换算成布局覆盖率。按[持续改进](improvement.md)接续，后续效果复验单独保留待办。

有界布局回归可以检查：条件提示出现时保持约定间距；多个提示同时出现时不粘连；隐藏提示后不留非预期空白。这些是需要按项目推导的布局关系示例，不是固定组件或统一间距值。

## 测试边界与覆盖率定义

建立“需求/风险 → 场景 → 用例 → 执行证据 → 问题/验收”的映射。至少区分：

| 证据 | 能证明什么 | 不能替代什么 |
| --- | --- | --- |
| 源码/静态约束 | 结构、类型或具体编码模式 | 行为成功或视觉正确 |
| 单元/模块行为 | 测试边界内给定输入的输出 | 真实数据库/权限/外部服务 |
| 数据库或服务集成 | 指定环境中的数据与服务交互 | 浏览器布局或第三方的真实环境 |
| 浏览器交互 | 实际页面状态和操作 | 未连接的服务或生产行为 |
| 渲染/视觉审阅 | 指定视口、状态、主题和内容 | 未审阅页面/状态或所有业务行为 |
| 真实外部/生产观察 | 指定目标和时间的观察结果 | 永久正确性或另一个候选版本 |

先定义场景集的范围和分母，例如角色/权限、主要流程、错误/边界、跨模块行为、回归和 UI 状态。场景集版本变化时说明原因和排除项。一个场景有多个用例时不能重复计为多个场景；若场景的任何必需断言失败，该场景就不能算通过。

- **设计覆盖率** = 有可执行用例的范围内场景 / 已确认的范围内场景。
- **执行覆盖率** = 在当前候选环境中已完成适用检查并记录结果的场景 / 已确认的范围内场景；失败也算已执行，跳过/阻塞不算完成。
- **通过覆盖率** = 在当前候选环境中所有适用必需检查均有效通过的场景 / 已确认的范围内场景。
- **执行通过率** = 通过的场景 / 已完成执行的场景；同时报告执行覆盖率，避免少量检查通过掩盖未测范围。
- **代码覆盖率**应单独报告工具、文件/包范围及行/分支/函数口径；它不是场景覆盖率。

报告分子/分母、范围基线、候选版本/环境、失败/跳过/未知项和排除项。分母尚未确认时，写“覆盖率尚不可计算”；不要根据测试文件数量猜测。阈值应依据项目风险和约定设定；不存在通用的 100% 要求。不要用总体百分比稀释本任务的关键验收条件。

## 验证预算与证据复用

先列出直接行为检查和项目要求的命令；需要时再检查受影响模块。影响较低的文档变更通常检查差异/引用即可；共享模块可检查使用方；高风险工作按项目要求验证，并安排独立审查。不要覆盖仓库强制门槛或省略失败检查。

当内容、输入、规格、工具/配置和环境均相同时，可以复用可靠的通过证据。候选版本变更时，先检查受影响范围；相关身份变化或检查失败意味着不能复用先前通过结果。记录无法运行检查的原因及剩余风险；必需验收尚未验证时仍为未通过。只记录实际使用的命令、Agent、模型和检查；计划不等于执行。
