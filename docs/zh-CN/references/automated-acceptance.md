# 自动验收与证据复用

初始化可执行门禁、判断任务是否具备验收条件或收尾时，使用本说明。随 skill 分发的执行器仅依赖 Python 3.9+ 标准库，写操作目前支持 macOS/Linux（POSIX 锁），不支持的加锁环境会明确拒绝：运行已审阅的项目命令、验证证据，并控制既有权威台账中声明的状态片段。项目自己的浏览器断言、设计基线和远端分支保护仍需实际接入。

## 判断哪些检查需要执行

逐项判断必需检查，不能把“存在记录”等同于“可以复用”。

| 既有证据 | 处理 |
| --- | --- |
| 回执通过、产物完整、输入/设计/检查定义/工具/环境匹配，且未超过适用有效期 | 直接复用，不重复执行测试 |
| 部分必需检查缺失或失效 | 只执行这些检查，保留未受影响的有效证据 |
| 必需用例失败、中断、不完整、跳过或未验证 | 门禁保持未通过，执行或解决对应检查 |
| 本任务没有可信验收证据 | 执行本任务完整的适用验收范围，不等于全仓库测试 |
| 来自其他系统的历史报告 | 由项目适配器核验原候选、环境、范围、结果及产物，来源保留为 validated-existing |
| 历史报告缺少必需关联 | 记录具体缺口并重跑对应检查，不丢弃其他有效证据 |

输入范围应包括会改变结果的实现及受影响依赖、设计/规格、测试、夹具、配置和锁文件。通配规则同时跟踪匹配路径与内容，新增或删除文件也会使证据失效。轻量探测获取真实浏览器/工具版本、环境或另一个已授权源码检出的身份；相关环境变量须明确声明，值仅保存哈希。未纳入范围的依赖变化无法自动发现，因此复用前必须审阅输入范围与验收用例。

## 项目接入时安装

1. 沿用项目已有验收命令和状态权威。将执行器复制到项目自有路径，例如 `scripts/delivery/acceptance_gate.py`，避免后续任务依赖个人 skill 安装目录。升级先比较维护版本，保留项目修改。
2. 创建本地配置，通常为 `.delivery/gate.json`，登记当前任务及实际适用命令/用例。不能用 `echo`、永远成功的脚本或仅搜索源码文字的断言代替真实检查。UI 用例须执行真实渲染断言及[交付门槛](delivery-gates.md)要求的设计对比。
3. 用唯一完成标记关联受管理任务与既有台账条目，台账仍是唯一任务状态来源。运行回执与完成证明属于证据，不另建任务板。历史任务不改写为刚刚验证，应按需逐步接入。
4. 将 `complete` 接入项目正常收尾入口，在授权范围内将 `audit` 接入已有检查/CI 入口，保留原检查。用一次拒绝完成及有效完成/复用演练验证接入。如果外部工单系统拥有状态，使用它支持的受控转换，不另建竞争状态。随包执行器直接支持的是已声明的本地台账。
5. 在实际生效的项目指令中写入门禁、配置、设计及记录路径；要求新实质任务执行前登记，收尾前验证当前候选，通过门禁完成。明确哪些入口已接通。只有脚本文件但未接入流程，不能称为已经执行门禁。

远端工作流、必需分支检查、权限或工单规则遵循项目授权。本地脚本无法阻止有写权限的人同时修改代码和证据；已接入的审计能发现无依据完成，更强的独立约束需要受保护的 CI 或任务系统。只有实际配置并验证后，才能宣称这种保护已启用。

## 配置与命令

命令使用参数数组且不经过 shell；配置视为可执行的项目代码，运行前审阅。使用隔离或只读检查，不能为补证据默默运行生产写入、付费服务或迁移。普通路径相对于选定项目根目录，且必须留在其中。

```json
{
  "version": 1,
  "evidence_dir": "artifacts/delivery-gate",
  "checks": {
    "notice-layout": {
      "kind": "ui",
      "command": ["node", "scripts/check-notice-layout.mjs"],
      "inputs": ["src/components/Notice.vue", "src/theme.css", "docs/design/notice.md", "scripts/check-notice-layout.mjs", "package-lock.json"],
      "required_cases": ["desktop-base", "desktop-notice", "narrow-notice"],
      "probes": {"version": ["node", "scripts/browser-version.mjs"]},
      "timeout_seconds": 120
    }
  },
  "tasks": {
    "UI-001": {
      "checks": ["notice-layout"],
      "completion": {
        "path": "docs/PROJECT.md",
        "pending": "<!-- delivery:UI-001 --> In progress",
        "done": "<!-- delivery:UI-001 --> Accepted (internal)"
      }
    }
  }
}
```

按真实路径、用例和项目状态调整示例。既有台账必须恰有一处对应 pending/done 状态片段，两者包含同一任务标记。`env_keys` 可声明其他环境输入；项目要求时间窗口时用 `max_age_seconds` 限制证据复用，不设通用过期时长。

```sh
python3 scripts/delivery/acceptance_gate.py plan --root . --task UI-001
python3 scripts/delivery/acceptance_gate.py run --root . --task UI-001
python3 scripts/delivery/acceptance_gate.py check --root . --task UI-001
python3 scripts/delivery/acceptance_gate.py complete --root . --task UI-001
python3 scripts/delivery/acceptance_gate.py audit --root .
```

- `plan` 报告可复用、缺失、失效或失败证据；`check` 验证当前候选，必需证据无效时返回非零。两者不运行完整测试命令，但可能执行已声明的轻量探测。
- `run` 仅执行没有有效通过证据的检查。`complete` 同样按需执行，再复核并只更新声明的状态片段。检查失败不改变台账，没有强制通过开关。
- 对已完成任务再次调用 `complete`，只验证原证明并返回历史验收，不重跑检查或替换原证明；完成标记缺少有效证明时拒绝。新候选须单独检查、建立新任务或明确重开原条目。
- `audit` 发现受管理已完成条目缺少完整完成证明的情况，按当时验收候选验证历史证据，不因今天无关修改而抹去历史。任务定义或必需检查变更会使完成证明失效。新候选是否具备条件应使用 `check`/`complete`，不能用历史 `audit` 通过代替。

完成流程先执行受控台账转换，最后发布通过证明。期间台账被其他工作修改、转换中断或最终证明写入失败时，审计保持不通过。若状态标记已经改变但证明没有成功发布，检查失败原因并显式重开条目后再重试，不能手工补造通过回执。

调用方必须处理 JSON 结果和退出码，不能忽略失败后自行写“完成”。完成仅证明配置中的验收范围，不表示已发布、用户批准、全覆盖或所有产品行为通过；证据仍保留验收日期与候选身份。

## 检查适配器合同

执行器提供全新的 `DELIVERY_RUN_DIR` 和 `DELIVERY_REPORT_PATH`，检查可以写入日志/产物，结构化报告写到指定路径。UI 检查须报告全部配置用例，每个编号恰有一条，并通过实际断言：

```json
{
  "provenance": "executed",
  "cases": [
    {"id": "desktop-notice", "status": "passed", "details": {"expected_gap": 12, "observed_gap": 12}}
  ]
}
```

上面一行只演示格式，并不是前述三用例配置的完整报告。必需用例缺失、重复、失败、跳过或未验证时，即使命令返回 0 也不能通过。普通命令检查可使用退出码，但 UI 检查仅有退出码不够。断言必须有意义，伪造结果的报告器不能证明正确。

验证完整历史证据的适配器使用 `provenance: "validated-existing"`，关联原证据并说明输入/环境如何匹配。必须检查原结果与身份，不能把“以前通过”的文字改造成新通过报告。历史元数据缺失仍是缺口。直接视觉审阅与自动几何分开，相关候选、基线和环境相同时才复用已记录审阅；必需人工证据须由明确的项目适配器核验，否则保持未验证。

执行器将回执关联到输入/检查/环境指纹及日志/报告哈希，拒绝过期证据，执行前先记录运行中或未通过状态，成功后才产生完成证明；还会检查执行中输入变化，并串行化自己的写操作。哈希检测漂移或意外损坏，不能抵御能重写所有本地文件的人伪造证据。遵守项目产物保留及隐私规则，不能为了让审计通过就提交秘密或所有临时证据。
